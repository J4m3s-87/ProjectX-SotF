================================================================================
                              1. PLAYER MODULE
================================================================================

PURPOSE:
Provides player quality-of-life features including teleportation of companions.

┌──────────────────────────────────────────────────────────────────────────────┐
│ HOW TO USE                                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ 1. Open the Project X menu (default: Insert key)                            │
│    NOTE: Menu is blocked when the Esc pause menu is open.                    │
│ 2. Navigate to the "Player" tab                                             │
│ 3. Toggle cheats on/off:                                                    │
│    • God Mode - Makes you invulnerable to all damage                        │
│    • Infinite Stamina - Never run out of energy                             │
│    • No Hunger - Hunger meter stays full                                    │
│    • No Thirst - Thirst meter stays full                                    │
│    • No Sleep - No tiredness                                                │
│    • Infinite Ammo - Weapons never need reloading                           │
│    • No Fall Damage - Survive any height                                    │
│    • Infinite Logs - Carry unlimited logs                                   │
│    • Infinite Stones - Carry unlimited stones                               │
│    • AI Ghost Player - AI ignores you                                       │
│    • Fill Inventory - Fill all items to max                                 │
│    • Max Strength - Sets player strength to max level (toggle)              │
│    • No World Gravity - Disable world gravity (uses debug console)         │
│                                                                              │
│ COMPANIONS (Teleport tab → "COMPANIONS" section):                            │
│ • Unstuck Kelvin / Unstuck Virginia — teleport 2m in front of you           │
│ • Revive Kelvin / Revive Virginia — revive via debug console                │
│   (removedead + addcharacter robby/virginia)                                │
│ • Virginia Visit — trigger Virginia to visit you (Virginiavisit)            │
│ • Happy Virginia — set Virginia sentiment to max (virginiasentiment 100)    │
│ • Enable Stat Overrides — master toggle for HP/damage multipliers          │
│ • Kelvin HP Multi — HP multiplier slider (1x–200x)                         │
│ • Virginia HP Multi — HP multiplier slider (1x–200x)                       │
│                                                                              │
│ HP multipliers apply:                                                        │
│  - On first-aid revival (VailActor.Revive postfix, 1s delayed)              │
│  - On actor spawn/load (VailActor.OnActorEnabled postfix)                   │
│  - Sliders auto-enable Stat Overrides when moved above 1.0                 │
│                                                                              │
│ MOVEMENT:                                                                    │
│ • Walk Speed, Run Speed, Swim Speed, Jump Multiplier sliders               │
│ • Reset Movement toggle — resets all to vanilla defaults (1.0)             │
└──────────────────────────────────────────────────────────────────────────────┘

CONFIG OPTIONS (Settings → Mods → ProjectX - Cheats):
- GodMode (bool): Enable invulnerability
- IsInfStamina (bool): Enable infinite stamina
- IsNoHungry (bool): Disable hunger
- IsNoDehydration (bool): Disable dehydration
- IsNoSleep (bool): Disable sleep requirement
- IsInfiniteAmmo (bool): Unlimited ammunition
- IsNoFallDamage (bool): Disable fall damage
- InfiniteLogs (bool): Unlimited log carrying
- InfiniteStones (bool): Unlimited stone carrying
- InfiniteInventory (bool): Set ALL items to 999,999,999

MOVEMENT OPTIONS (Settings → Mods → ProjectX - Movement):
- IsNoClip (bool): Fly mode
- NoClipSpeed (float, 0.5-20): Flight speed
- NoClipUpDownSpeed (float, 0.1-10): Vertical flight speed
- WalkSpeed (float, 0.1-10): Walk speed multiplier
- RunSpeed (float, 0.1-10): Run speed multiplier
- SwimSpeed (float, 0.1-10): Swim speed multiplier
- JumpMultiplier (float, 0.5-10): Jump height multiplier
- IsNoGravity (bool): Float when jumping

INTERNAL MECHANICS:
- Kelvin internal name: "Robby", "Robby0", "Robby1"...
- Virginia internal name: "Virginia0", "Virginia1"...
- Uses VailActor.SetPositionAndRotation() for teleportation

                              3. ZIPLINE MODULE
================================================================================

PURPOSE:
Extends zipline construction distance and rope gun firing range.

┌──────────────────────────────────────────────────────────────────────────────┐
│ HOW TO USE                                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ This module works AUTOMATICALLY once configured.                             │
│                                                                              │
│ CONFIGURE ZIPLINE DISTANCES:                                                 │
│ 1. Go to Settings → Mods → Project X                                       │
│ 2. Find the "Zipline" section                                               │
│ 3. Set your preferred values:                                               │
│    • MaxZipLineLength: How long the zipline rope can be                     │
│    • MaxRopeBridgeLength: How far rope bridges can span                     │
│    • MaxShootingDistance: How far the rope gun can shoot                    │
│                                                                              │
│ IN-GAME USAGE:                                                               │
│ 1. Equip the Rope Gun                                                       │
│ 2. Aim at a distant anchor point                                            │
│ 3. The extended range lets you shoot much farther than vanilla!             │
│ 4. Build rope bridges spanning valleys that were previously impossible      │
│                                                                              │
│ DEFAULT VALUES:                                                              │
│ • Vanilla zipline length: ~40m                                              │
│ • Modded zipline length: 200m (5x farther!)                                │
└──────────────────────────────────────────────────────────────────────────────┘

CONFIG OPTIONS:
- MaxZipLineLength (float): Maximum zipline rope length
  Default: 200m
  
- MaxRopeBridgeLength (float): Maximum rope bridge construction length
  Default: 200m
  Note: Internally divided by 400 for API (e.g., 200m = 0.5 internal)
  
- MaxShootingDistance (float): Rope gun maximum firing range
  Default: 200m

INTERNAL MECHANICS:
- Modifies RopeGunController._maxRopeLength
- Modifies RopeGunController._maxFiringRange
- Modifies ConstructionSettings.Targeting.MaxRopeBridgeLength
- Uses polling pattern (non-Harmony) for IL2CPP compatibility

================================================================================

PURPOSE:
Allows structures to be picked up and relocated without being destroyed.

┌──────────────────────────────────────────────────────────────────────────────┐
│ HOW TO USE                                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ This module works AUTOMATICALLY - no extra steps needed!                     │
│                                                                              │
│ TO RELOCATE A STRUCTURE:                                                     │
│ 1. Approach any built structure (traps, furniture, decorations, etc.)       │
│ 2. Look at it and hold the "Relocation" key (check game controls)           │
│ 3. The structure becomes moveable - place it in the new location            │
│ 4. Confirm placement                                                        │
│                                                                              │
│ WHAT CAN BE RELOCATED:                                                       │
│ • Traps (deadfall traps, etc.)                                              │
│ • Utility items (drying racks, etc.)                                        │
│ • Furniture (beds, chairs, benches)                                         │
│ • Decorations (skull lamps, etc.)                                           │
│ • Shelters (log cabins, tents)                                              │
│                                                                              │
│ NOTE: In vanilla game, many structures can only be destroyed when moved.    │
│ This mod lets you pick them up and reposition them instead!                 │
└──────────────────────────────────────────────────────────────────────────────┘

CATEGORY TYPES:

│ 4           │ Shelters   │ Log cabin                         │
└───────────────────────────────────────────────────────────────┘

================================================================================
                          6. WATER COLLECTORS MODULE
================================================================================

PURPOSE:
Prevents rain catchers from freezing in winter when near a fire source.

┌──────────────────────────────────────────────────────────────────────────────┐
│ HOW TO USE                                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ This module works AUTOMATICALLY in winter.                                   │
│                                                                              │
│ TO KEEP RAIN CATCHERS UNFROZEN IN WINTER:                                   │
│ 1. Build a Rain Catcher as normal                                           │
│ 2. Build a FIRE nearby (standing fire, campfire, etc.)                      │
│ 3. Keep the fire LIT                                                        │
│ 4. As long as the catcher is within the heat radius, it won't freeze!      │
│                                                                              │
│ CONFIGURING HEAT RADIUS:                                                     │
│ 1. Go to Settings → Mods → Project X                                       │
│ 2. Find "WaterCollectorHeatRadius"                                          │
│ 3. Set the detection distance (default: 10 meters)                          │
│                                                                              │
│ TIPS:                                                                        │
│ • Place multiple catchers around one central fire                           │
│ • Make sure the fire stays burning!                                         │
│ • The effect only matters in Winter (Season 3)                              │
└──────────────────────────────────────────────────────────────────────────────┘

CONFIG OPTIONS:
- WaterCollectorHeatRadius (float): Detection radius for fire sources
  Default: 10m

FIRE DETECTION (Updated Feb 08 2026):
- Harmony Postfix on TemperatureModifierVolume.OnEnable() tracks all heat
  sources in a static list (Physics.OverlapSphere is stripped by IL2CPP)
- Uses Vector3.Distance checks against tracked heat sources
- Searches for objects with tag prefix "Fire" (covers all fire variants)
- State-cached: SetFrozen() only called on state transitions, not every tick

INTERNAL MECHANICS:
- Harmony Postfix on RainCatcher.Attached() to track all catchers
- OnGuiTick() piggybacked on ProjectXGUI.OnGUI() for scanning loop
- Uses reflection MethodInfo for SetFrozen(bool) on RainCatcher
- HashSet<int> tracks unfrozen catcher instance IDs (state caching)
- Heat source list cleanup every ~60s (null reference pruning)
- Calls RainCatcher.SetFrozen(false) when fire nearby in winter
- Calls RainCatcher.SetFrozen(true) when no fire nearby in winter

                             7. MEAT DRYER MODULE
================================================================================

PURPOSE:
Modifies drying rack behavior based on season and proximity to heat sources.
Meat dries faster when near a fire, with speed varying by season.

┌──────────────────────────────────────────────────────────────────────────────┐
│ HOW TO USE                                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ This module works AUTOMATICALLY on all drying racks.                         │
│                                                                              │
│ TO MAXIMIZE MEAT DRYING SPEED:                                               │
│ 1. Build a Drying Rack                                                      │
│ 2. Place meat/fish on the rack                                              │
│ 3. Build a FIRE nearby to create a "temperature volume"                     │
│ 4. The drying speed bonus is applied automatically!                         │
│                                                                              │
│ SEASON EFFECTS:                                                              │
│ ┌─────────┬──────────────┬───────────────────────────────────┐             │
│ │ Season  │ Drying Boost │ Min Temp Required                 │             │
│ ├─────────┼──────────────┼───────────────────────────────────┤             │
│ │ Spring  │ 30x faster   │ 20°C (easy - small fire works)   │             │
│ │ Summer  │ 25x faster   │ 15°C (easiest - any fire works)  │             │
│ │ Autumn  │ 15x faster   │ 30°C (medium - need good fire)   │             │
│ │ Winter  │ 5x faster    │ 50°C (hard - need big fire!)     │             │
│ └─────────┴──────────────┴───────────────────────────────────┘             │
│                                                                              │
│ CONFIGURING CHECK INTERVAL:                                                  │
│ Settings → Mods → Project X → MeatDryerProximityCheckInterval               │
│ Default: 5 seconds (how often the mod checks temperature)                   │
│                                                                              │
│ TIPS:                                                                        │
│ • Summer is the BEST season for drying (low temp requirement, high boost)  │
│ • Winter is the WORST (need a huge fire for minimal boost)                 │
│ • Place racks CLOSE to fires for best results                              │
└──────────────────────────────────────────────────────────────────────────────┘

CONFIG OPTIONS:
- MeatDryerProximityCheckInterval (float): How often to check temperature
  Default: 5.0 seconds

INTERNAL MECHANICS:
- Recipe ID 19 = Drying Rack Prefab
- Season Values: 0=Spring, 1=Summer, 2=Autumn, 3=Winter
- Injects MeatDryerController component into Drying Rack prefab
- Modifies DryingRackHookPoint._isInsideTemperatureVolume
- Modifies DryingRackHookPoint._dryBoostMultiplier
- Modifies DryingRackHookPoint._minTemperatureToGainDryBoost
- Reads SeasonsManager._activeSeason via cached reflection

================================================================================
                            8. SCARY CROSS MODULE
================================================================================

PURPOSE:
Transforms the buildable Cross structure into a functional demon-repelling
effigy that scares away enemies when powered and can even burn them.

┌──────────────────────────────────────────────────────────────────────────────┐
│ HOW TO USE                                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ BUILDING A SCARY CROSS:                                                      │
│ 1. Build a Cross structure (found in building menu)                         │
│ 2. Connect it to ELECTRICITY (solar panels + batteries)                     │
│ 3. The cross is now active!                                                 │
│                                                                              │
│ HOW IT WORKS:                                                                │
│ • When powered, the cross has a "demon detection" radius                    │
│ • When demons/cannibals enter the radius, the lights glow brighter          │
│ • The more enemies nearby, the hotter the cross gets                        │
│ • At high heat, the cross CATCHES FIRE and scares/burns enemies            │
│ • CAUTION: The fire damages the cross structure over time!                  │
│                                                                              │
│ EFFECT PROGRESSION:                                                          │
│ 1. Demons approach → Lights start glowing                                   │
│ 2. More demons → Lights get brighter, temperature rises                     │
│ 3. Temperature threshold → Cross catches fire!                              │
│ 4. Fire scares demons away (effigy effect)                                  │
│ 5. Fire can BURN demons within range                                        │
│ 6. Continued fire → Cross takes damage and eventually breaks               │
│                                                                              │
│ TIPS:                                                                        │
│ • Place crosses at your base perimeter for protection                       │
│ • Keep spare materials to rebuild burned crosses                            │
│ • Multiple crosses = better coverage                                        │
│ • Works best with consistent power supply                                   │
└──────────────────────────────────────────────────────────────────────────────┘

CONFIG OPTIONS (Advanced - Settings → Mods → Project X):
┌──────────────────────────────────────────────────────────────────────────────┐
│ Setting                    │ Purpose                                         │
├────────────────────────────┼─────────────────────────────────────────────────┤
│ SC_TempRiseThreshold       │ Light intensity needed to start heating         │
│ SC_BurnThreshold           │ Temperature to start burning                    │
│ SC_DamageThreshold         │ Temperature to start taking damage              │
│ SC_DamageAfterSec          │ Seconds between damage ticks                    │
│ SC_LightIntensityRise      │ Light intensity increase per second             │
│ SC_LightIntensityReduce    │ Light intensity decrease per second             │
│ SC_TempRisePerSec          │ Temperature increase per second                 │
│ SC_TempReducePerSec        │ Temperature decrease per second                 │
│ SC_EffigyMinRange          │ Minimum effigy scare range                      │
│ SC_EffigyMaxRange          │ Maximum effigy scare range                      │
│ SC_EffigyMinStrength       │ Minimum effigy scare strength                   │
│ SC_EffigyMaxStrength       │ Maximum effigy scare strength                   │
│ SC_EffigyDisabledRange     │ Effigy range when unpowered                     │
│ SC_EffigyDisabledStrength  │ Effigy strength when unpowered                  │
│ SC_BurnDemonRangeMin       │ Minimum demon burn range                        │
│ SC_BurnDemonRangeMax       │ Maximum demon burn range                        │

└──────────────────────────────────────────────────────────────────────────────┘

INTERNAL MECHANICS:
- Recipe ID 71 = Cross Recipe
- Item ID 468 = Cross (Held)
- Profile ID 403 = Standing Fire (for fire effects)
- Injects MakeCrossScary component
- Uses DemonDetector component for enemy detection

                         11. LOOT RESPAWN MODULE  *** UPDATED ***
================================================================================

BASED ON: GlaDOS (laserman120) — LootRespawnControl v2
  https://github.com/laserman120/SOTF-Mod-LootRespawnControl (AGPL-3.0)

PURPOSE:
Tracks collected loot items, opened containers, and broken crates, allowing
them to respawn after a configurable number of in-game days. All item types
are tracked with unique positional identifiers. After the respawn timer
expires, items re-appear and containers reset when the area reloads.

*** UPDATED: SERVER-AUTHORITATIVE TRACKING (March 09, 2026) ***
On dedicated servers, all tracking uses LootSyncEvent (Packets.NetEvent,
scope "ProjectX.LootSync") — a dedicated binary protocol replacing the
original debugCommand relay. Clients report collections via 0x01/0x02/0x03
messages; server broadcasts suppressions via 0x20 (full sync) and 0x21
(incremental). Container events (break/open) fire server-side directly.
The server persists to loot_collected.dat in UserData/ (SFTP-visible).

*** FIXED: CONTAINER RESPAWN (March 09, 2026) ***
Timer-expired containers are now REMOVED from _collected and the PREFIX
returns true (allowing player interaction). Previously, expired containers
were kept in _collected and added to _recentlyRespawned, which permanently
blocked all future interaction. _recentlyRespawned now only blocks during
streaming (save-load phase); once _saveDataLoaded=true, players interact
normally and the hash is removed from the set.

*** FIXED: COMPLETE ITEM SUPPRESSION (March 11, 2026) ***
Suppressed items are now fully hidden and non-interactable:
  - transform.localScale = Vector3.zero (hides 3D model)
  - _PickupGui_ child GameObject deactivated (hides floating icon)
  - All colliders recursively disabled (prevents interaction)
  - PickUp component disabled (prevents collection)
RestorePickup() reverses all of the above when timer expires mid-session.
Only applied when item was actually suppressed (scale==zero guard prevents
giant icon bug on fresh game instances).

*** CHANGED: GPS LOCATOR CATEGORY (March 11, 2026) ***
GPS Locator (itemId 529) moved to Meds category for respawn timer purposes.
Previously uncategorized (fell through to global timer).

*** FIXED: RESPAWN DAYS UI (March 09, 2026) ***
Replaced slider with text input + "Set" button in Server Admin panel.
Slider was spamming ServerCmd on every drag tick causing lag.

KEY DIFFERENCES FROM ORIGINAL:
- Integer hash for pickups (original uses MD5 — bottleneck with 600+ Awake calls)
- Standalone JSON persistence (original uses game save system ICustomSaveable)
- Manual Harmony patching (original uses HarmonyPatchAll = true)
- Clone filtering: explicit skip for (Clone) items from containers
- 2 config options + per-category toggles + item whitelist/blacklist
  (original has 50+ per-category allow/block/timed/sync)
- Container respawn (openable + breakable + GrabBag) is ENTIRELY NEW —
  the original mod only handles ground pickups, not containers
- Server-authoritative tracking via LootSyncEvent is ENTIRELY NEW —
  the original mod has no multiplayer/server support

INTERNAL MECHANICS:

Ground Pickups:
- Harmony Postfix on PickUp.Awake(): Checks suppression table on spawn
- Harmony Postfix on PickUp.Collect(): Records collection with timestamp
- Identifier: Integer hash combining (name.GetHashCode() + quantized position)
  Previously used MD5 — replaced for performance (600+ PickUp.Awake calls
  during world load made MD5.Create()+ComputeHash() a bottleneck)
- Early-exit guard: if suppression dictionary is empty, Awake hook is no-op

Suppression/Restoration:
- SuppressPickup(Transform, PickUp): Hides item completely
  • Sets transform.localScale = Vector3.zero
  • Finds _PickupGui_ child via Transform.Find, calls SetActive(false)
  • DisableCollidersRecursive: walks hierarchy disabling all Colliders
  • Sets pickup.enabled = false
- RestorePickup(Transform, PickUp): Reverses suppression mid-session
  • Restores transform.localScale = Vector3.one
  • Re-activates _PickupGui_ child
  • EnableCollidersRecursive: walks hierarchy re-enabling all Colliders
  • Sets pickup.enabled = true
  • Only called if item was actually suppressed (localScale == Vector3.zero)
    This guard prevents giant icon bug on fresh game instances where the
    item already has its correct original scale

Openable Containers:
- Harmony PREFIX on ContainerItemSpawner.OpenContainer(): Blocks streaming
  replays (spawnItems=false) for expired entries in _collected
- Harmony POSTFIX on ContainerItemSpawner.OpenContainer(): Records fresh
  opens during gameplay
  • LOCAL PLAY: tracks spawnItems=False call (player opened signal)
  • DEDICATED SERVER: tracks spawnItems=True + contentsSeed>0 + saveDataLoaded
    (On servers, OpenContainer always fires with spawnItems=True for player opens.
     The spawnItems=False calls only happen during deserialization/streaming.)
- Does NOT call ClearStateSync (breaks container interaction)

Breakable Containers:
- Harmony PREFIX on BreakableObject.OnBreak(): Frame-based blocking
  (≤120 frames of Awake) + expired timer fallback from _collected
- Harmony POSTFIX on BreakableObject.OnBreak(): Records break events
- IsNonLootBreakable() filter: skips BreakableSticksInteraction,
  SmallGroundStickPile*, BreakableStump*, and "Unbroken" objects.
  These are environment objects (stick piles, stumps, player structures) —
  not loot containers. Applied to Awake, PREFIX, and POSTFIX hooks.
- ClearContainerSaveState(): Finds child ContainerItemSpawner, calls
  ClearStateSync() + set__isOpen(false) for fresh loot contentsSeed
- _breakableLoadFrame dictionary tracks frame count per breakable hash
- OnBreak fires on the dedicated server (via Harmony) — server records directly

Shared:
- Timer: RespawnDays × 1440 seconds (1 in-game day ≈ 1440 seconds)
- Timer-expired entries are REMOVED from _collected (container is truly fresh)
- _recentlyRespawned HashSet blocks streaming replays only (not player interaction)
  Once _saveDataLoaded=true, _recentlyRespawned entries allow through + get removed
- Manual Harmony patching (HarmonyPatchAll=false for IL2CPP safety)
- Runs on all deployment tiers (Owner, Server, Client)
- Save path: UserData/ via LoaderEnvironment.UserDataDirectory (SFTP visible)

Dedicated Server Lifecycle Fix (Phase 344):
  On dedicated servers, OnSdkInitialized does NOT fire, so Init() runs inside
  OnGameStart() — AFTER OnGameStarted() has already set _saveDataLoaded=true.
  Init() unconditionally reset _saveDataLoaded=false, breaking all tracking.
  Fix: Init() preserves _saveDataLoaded if already true. OnSceneInit() also
  skips reset if _saveDataLoaded is already true (prevents post-game scene
  inits from resetting the tracker).

LootSyncEvent Network Protocol (March 09, 2026):
  Replaced debugCommand relay with dedicated LootSyncEvent (Packets.NetEvent).
  Scope: "ProjectX.LootSync". Binary messages:
  - 0x01 C→S: Pickup collected (hash + itemId)
  - 0x02 C→S: Container broken (hash)
  - 0x03 C→S: Container opened (hash)
  - 0x10 C→S: Request full suppression list
  - 0x20 S→C: Full suppression list (all hashes)
  - 0x21 S→C: Incremental suppress (single hash, broadcast to all)
  Server tracks client connections in _trackedClients HashSet.
  Client clears _collected on join, requests 0x10, applies 0x20 state.

LootEventListener (debugCommand fallback — still used for C→S pickups):
- C→S transport via Bolt's debugCommand event (bolt.user.dll)
- LootSyncEvent 0x01 is defined but pickup collection still uses debugCommand
  as a proven C→S path. Containers (0x02/0x03) use LootSyncEvent directly.
- LootEventListener still registered as GlobalEventListener for this path

                    15. BUILDER STACKS MODULE  *** NEW ***
================================================================================

PURPOSE:
Carry more logs, planks, and stones beyond vanilla limits using a virtual buffer.
Based on ItemCarryAmount 1.0.0 by mΔ, rewritten for IL2CPP with per-material
capacity, native visual stacking, and configurable limits.

┌──────────────────────────────────────────────────────────────────────────────┐
│ HOW TO USE                                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ 1. Go to Settings → Mods → Project X → Builder Stacks                       │
│ 2. Enable Builder Stacks (toggle on)                                        │
│ 3. Set Max Log Capacity, Max Plank Capacity, Max Stone Capacity             │
│    (type exact numbers — e.g. "4", "8", "12")                               │
│ 4. Enable Max Limit must be ON for the cap to take effect                   │
│ 5. Pick up materials normally — the mod buffers excess items invisibly      │
│ 6. When you place one, the next item is given back from the buffer          │
│ 7. A HUD panel shows the material icon + carry count (e.g. "4/8")       │
└──────────────────────────────────────────────────────────────────────────────┘

HOW IT WORKS:

When ENABLED with max limit ON:
  - Player picks up materials normally. Game shows vanilla visual stacking
    (logs stack to 2 on shoulder, planks/stones stack to 4)
  - When hands reach the native hold limit, excess items are absorbed into
    an invisible buffer and _heldCount is reset
  - Total carry = buffer + native hold limit = configured max capacity
  - When the player places an item and hands become empty, the mod waits
    a short delay then gives one back from the buffer via TryEquip
  - At capacity: mod does nothing, game enforces native hold limit

When ENABLED with max limit OFF:
  - No cap — carry unlimited materials

When DISABLED:
  - Reverts to vanilla carry limits (2 logs, 4 planks, 4 stones)

NATIVE HOLD LIMITS (vanilla game):

│ Stones   │ 4           │ 4 on shoulder│ ID: 640               │

CONFIGURATION:

              19. NETWORK INFRASTRUCTURE MODULE  *** NEW ***
================================================================================

PURPOSE:
Server-authoritative networking layer that provides:
  1. Config Sync — Server broadcasts all config values to clients on join
  2. RBAC — Role-Based Access Control via roles.json (Owner/Admin/Mod/Player)
  3. Permission Sync — Server broadcasts per-player permissions to clients
  4. Integrity Check — Anti-cheat mod whitelist + DLL hash verification
  5. Admin Command Bridge — Client→Server command relay via ChatBox.SendLine
  6. Command Bridge — Server-side ChatEvent interception for admin commands

This module is the backbone of the 4-Tier Architecture (Solo/Owner/Client/Server).
It ensures that all players receive identical game settings and that only
authorized players can access admin features.

┌──────────────────────────────────────────────────────────────────────────────┐
│ SUB-COMPONENTS                                                               │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│ ┌─ CONFIG SYNC (ConfigSyncEvent + ConfigSyncPayload) ──────────────────┐    │
│ │ • Server serializes all Config.cs entries into a key=value payload    │    │
│ │ • Sends 0x10 PAYLOAD packet to each client on join                   │    │
│ │ • Re-broadcasts to ALL clients on config change (live update)        │    │
│ │ • Client applies received values via ConfigSyncPayload.Apply()       │    │
│ │ • Protocol: 0x01 = client request, 0x10 = server payload             │    │
│ │ • Buffer: 8192 bytes per packet (~4KB payload typical)               │    │
│ └──────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│ ┌─ RBAC: ROLE MANAGER (RoleManager + roles.json) ─────────────────────┐    │
│ │ • 4-tier role hierarchy: Player(0) → Moderator(1) → Admin(2) → Owner(3)  │
│ │ • Loaded from roles.json at mod startup (server/owner only)          │    │
│ │ • Maps SteamID → Role via hand-parsed JSON (no external deps)        │    │
│ │ • Auto-creates default template if roles.json doesn't exist          │    │
│ │ • Public API: GetRole(steamId), HasRole(steamId, role),              │    │
│ │   IsAdmin(steamId), IsOwner(steamId)                                 │    │
│ │ • Used by PermissionEvent, IntegrityEvent, and DedicatedSuperuser    │    │
│ └──────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│ ┌─ PERMISSION SYNC (PermissionSync + PermissionEvent) ────────────────┐    │
│ │ • Server broadcasts HasMenuAccess, HasAdminAccess, CurrentRole       │    │
│ │ • Client receives via 0x02 response packet and applies locally       │    │
│ │ • Owner edition: always has full access (no server query)             │    │
│ │ • Solo: full access by default                                       │    │
│ │ • Server can grant/revoke menu access per-player by name             │    │
│ │ • Session cheats toggle broadcasts to all clients                    │    │
│ └──────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│ ┌─ INTEGRITY CHECK / ANTI-CHEAT (IntegrityEvent + IntegrityConfig) ───┐    │
│ │ • 3-way handshake on player join:                                    │    │
│ │   1. Server → Client: 0x10 REQUEST_CHECK (Packets.NetEvent)         │    │
│ │   2. Client → Server: /px integrity mod1,mod2|hash (ChatBox.SendLine)│   │
│ │   3. Server → Client: 0x12 CHECK_RESULT pass/fail (Packets.NetEvent)│    │
│ │ • Hybrid protocol: NetEvent server→client, ChatBox client→server     │    │
│ │   (because Packets.NetEvent client→server is silently dropped on     │    │
│ │    dedicated servers — documented limitation)                         │    │
│ │ • Client collects loaded mods via ModTypeBase<SonsMod>.RegisteredMods│    │
│ │ • Client hashes own DLL via SHA256                                   │    │
│ │ • Server validates against whitelist + expected hash                  │    │
│ │ • Timeout = ALLOW (vanilla clients can't respond = likely safe)      │    │
│ │ • Only explicit whitelist violations trigger disconnect               │    │
│ │ • Deferred queue: connection events fire on Bolt background threads; │    │
│ │   requests are queued and dispatched on main thread via tick driver   │    │
│ │ • Retry mechanism: client retries sending response up to 30 times    │    │
│ │   (1/sec) if ChatBox isn't available during loading                  │    │
│ └──────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│ ┌─ ADMIN COMMAND BRIDGE (AdminCommandEvent) ──────────────────────────┐    │
│ │ • Routes GUI admin panel commands from client to server              │    │
│ │ • PRIMARY: ChatBox.SendLine (game's own chat → server via Bolt)      │    │
│ │ • SECONDARY: ChatEvent.Create(GlobalTargets.Everyone) — fallback     │    │
│ │ • TERTIARY: Local execution (single player only)                     │    │
│ │ • ChatBox type resolved at runtime via AccessTools.TypeByName        │    │
│ │ • SendLine method invoked via reflection (private method)            │    │
│ └──────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│ ┌─ COMMAND BRIDGE (CommandBridge) ────────────────────────────────────┐     │
│ │ • Server-side ChatEvent listener for "/px" prefixed commands         │    │
│ │ • Routes commands to appropriate handlers (DedicatedSuperuser, etc.) │    │
│ │ • Intercepts chat messages before they reach other players           │    │
│ └──────────────────────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────────────────────┘

CONFIG OPTIONS (IntegrityCheck — Server-side only):

                     22. CRAFTING SPEED MODULE  *** UPDATED ***
================================================================================

BASED ON: FasterCrafting by unknown
  Concept studied, independently implemented with CraftingCog event hook.

PURPOSE:
Speeds up backpack crafting animations by setting the CraftingSystem's
consecutive crafting speed to the configured multiplier on each craft event.

┌──────────────────────────────────────────────────────────────────────────────┐
│ HOW TO USE                                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ This module works AUTOMATICALLY once enabled.                                │
│                                                                              │
│ TO CONFIGURE:                                                                │
│ 1. Go to Settings → Mods → ProjectX - Features                              │
│ 2. Toggle "Faster Crafting" on/off                                          │
│ 3. Set "Crafting Speed Multiplier" (1.0 - 10.0):                            │
│    • 1.0 = Normal speed (vanilla)                                           │
│    • 5.0 = 5x faster (default)                                              │
│    • 10.0 = 10x faster (near-instant)                                       │
│                                                                              │
│ HOW IT WORKS:                                                                │
│ 1. Open your backpack (Tab)                                                  │
│ 2. Place items on the crafting mat                                           │
│ 3. Click the cog to craft — crafting runs at the set speed                  │
│ 4. No ramp-up period — max speed from the first craft                       │
│                                                                              │
│ NOTES:                                                                       │
│ • Fish Trap (ID 707) is excluded — always crafts at 1x speed               │
│ • Speed applies immediately — no restart needed                             │
└──────────────────────────────────────────────────────────────────────────────┘

CONFIG OPTIONS:
- FasterCraftingEnabled (bool): Enable/disable faster crafting. Default: true
- CraftingSpeedMultiplier (float): Speed multiplier. Default: 5.0, Range: 1.0-10.0

INTERNAL MECHANICS:
- Harmony PREFIX on CraftingCog.OnCraftBeginEvent()
  Sets CraftingSystem properties before the crafting animation plays:
  • _consecutiveCraftsOfTheSameItem = 100 (skips ramp-up)
  • _consecutiveItemCraftingSpeedIncrease = 0.25
  • _maxConsecutiveItemCraftingSpeed = configured multiplier
- Uses manual harmony.PatchAll(typeof(CraftingCogPatch)) — NOT HarmonyPatchAll
- Fish Trap exclusion: checks recipe._resultingItems for ID 707
- Client-only module (#if !SERVER)

FILES:
 - Modules/Crafting/CraftingSpeed.cs  (patch + speed logic)

================================================================================
                         23. HOTBAR MODULE  *** NEW ***
================================================================================

BASED ON: SonsHotbar 1.1.1 by AEDEV
  Concept and slot logic studied, rebuilt with sprite caching and frame throttling.

PURPOSE:
Displays hotkey-assigned item icons on-screen, showing which items are mapped
to the number keys (1-0). Icons update automatically based on inventory state.

┌──────────────────────────────────────────────────────────────────────────────┐
│ HOW TO USE                                                                   │
├──────────────────────────────────────────────────────────────────────────────┤
│ This module works AUTOMATICALLY.                                             │
│                                                                              │
│ 1. Assign items to hotkeys as normal (hold item + press 1-0)                │
│ 2. A visual bar appears at the bottom of the screen showing:                │
│    • Item icon for each assigned hotkey slot                                 │
│    • Missing icon (X) if the item is not in inventory                       │
│ 3. The hotbar auto-hides during pause menu                                  │
│                                                                              │
│ TO CONFIGURE:                                                                │
│ Go to Settings → Mods → ProjectX - Hotbar:                                   │
│ • HotbarEnabled (bool): Toggle hotbar on/off. Default: true                 │
│                                                                              │
│ NOTES:                                                                       │
│ • Icons are cached after first lookup — no repeated texture creation        │
│ • Updates every 10 frames (not every frame) for performance                 │
│ • Works with both right-hand and left-hand hotkey assignments               │
└──────────────────────────────────────────────────────────────────────────────┘

CONFIG OPTIONS (Settings → Mods → ProjectX - Hotbar):
- HotbarEnabled (bool): Show/hide the hotbar. Default: true

INTERNAL MECHANICS:
- Prefab: Loaded from ModAssets.HotbarPrefab (bundled asset)
- Reads ItemHotkeyController._hotkeySaveData for slot assignments
- Slot mapping: GetSlotId() maps index 0→9 and 1-9→0-8 (keyboard layout)
- Sprite retrieval: ItemDatabaseManager.ItemById(id).UiData._icon
  • DummyDll compile-time types don't inherit Il2CppObjectBase at compile time.
    At RUNTIME they DO. Uses reflection Cast<Texture2D>() via Il2CppInterop
    to bypass the generic constraint. Sprite.Create() from the cast Texture2D.
- Frame throttling: UPDATE_INTERVAL = 10 frames between updates
- Dictionary<int, Sprite> cache avoids re-creating sprites each update
- Canvas toggle: disabled during PauseMenu.IsActive or when config is off
- Client-only module (#if !SERVER)

FILES:
 - Modules/Hotbar/HotbarModule.cs  (slot display + sprite caching)
 - Modules/Hotbar/ModAssets.cs      (prefab + missingIcon references)
